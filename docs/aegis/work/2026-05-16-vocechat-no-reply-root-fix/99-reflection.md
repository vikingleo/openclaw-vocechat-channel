# VoceChat no-reply root fix - Reflection

## Goal

Stop VoceChat inbound turns from going silent when OpenAI Responses streaming fails or when a queue item times out.

## DeeperCause

No further actionable deeper cause found inside the VoceChat extension.

- Stream failure cause: bundled OpenAI SDK parsed empty SSE `data` generated by event-only frames, matching live logs.
- Silence cause: VoceChat intentionally blocked late replies after timeout but did not send a terminal user-visible notice at timeout.

## Evidence

See `90-evidence.md`.

## Risk / Unknown

- The OpenAI SDK patch is a local startup patch over installed package files, so future OpenClaw upgrades still need the ExecStartPre patch to match the installed SDK file shape.
- Timeout notification delivery depends on VoceChat HTTP send succeeding at timeout time; failures are logged.

## Repair Track

- Repaired OpenAI SDK stream parse boundary by skipping empty SSE data before JSON parsing.
- Repaired VoceChat timeout path by sending a queue timeout fallback notice while preserving late reply blocking.

## Retirement Track

- Existing OpenClaw fetch-level SSE sanitizer remains active as upstream defense.
- New SDK patch can be retired when the installed OpenAI SDK or OpenClaw stream layer natively ignores empty SSE data frames across all loaded SDK copies.
